# 视频工具扩展规划

基于当前仓库已有的 `/transcribe` 和 `/api/transcribe` 链路，优先复用现有解析、会员、额度和多语言体系，扩展成一个完整的视频处理工具套件。

## 现有可复用能力

- `src/routes/transcribe.tsx`
- `src/blocks/video-transcriber.tsx`
- `src/routes/api/transcribe.ts`
- `src/routes/tools/index.tsx`
- `src/blocks/header.tsx`
- `src/blocks/footer.tsx`
- `src/routes/sitemap[.]xml.ts`

这些文件已经覆盖了：

- 会员校验
- 公开视频解析
- 音频转文字
- TXT / SRT 导出
- 多语言页面
- 工具总览入口

## 要新增的功能

### 1. 视频转文字

继续作为主入口。

用途：

- 公共公开视频转写
- 会员功能主卖点
- 作为其他工具的基础输入层

建议能力：

- 纯文本转写
- 带时间轴转写
- TXT / SRT 导出
- 语言自动识别
- 长视频分段处理

### 2. 视频总结 / 视频转文章

基于转写结果生成二次内容。当前已开始落地“视频总结”独立页与 API。

建议输出：

- 3 句摘要
- 详细要点
- 文章版长摘要
- 标题建议
- 关键词提取

### 3. 视频抽帧

从公开视频中按时间间隔截取关键帧。当前也已开始落地独立页面。

当前“音频提取”也已开始落地，直接复用现有公开视频解析链路。

建议输出：

- 固定间隔抽帧
- 智能关键帧抽取
- 缩略图网格
- 单图下载

### 4. 视频音频提取

把视频解析结果直接转成音频文件或音频直链。

建议输出：

- MP3 / M4A / AAC
- 音频预览
- 一键复制音频直链

### 5. 视频歌曲识别

用于识别背景音乐或片段歌曲。

当前也已开始落地独立页面与识别 API。

建议输出：

- 歌曲名
- 歌手
- 专辑信息
- 识别成功率 / 失败重试

## 页面结构建议

建议新增这些内页：

- `/transcribe`
- `/video-summary`
- `/frame-extractor`
- `/audio-extractor`
- `/song-recognizer`

其中 `/transcribe` 可以继续保留为主入口，并逐步和 `/tools/video-transcriber` 对齐。

## 后端拆分建议

### 第一层：解析层

职责：

- 输入公开视频 URL
- 返回 mediaUrl / audioUrl / metadata
- 失败后支持重试

### 第二层：转写层

职责：

- 读取音频直链
- 调用转写服务
- 生成文本、时间轴、导出格式

### 第三层：派生层

职责：

- 总结：复用转写结果再生成
- 抽帧：按时间点取图
- 音频提取：直接封装媒体流
- 歌曲识别：走独立识别接口

## 商业化分层

### 免费版

- 解析预览
- 限长视频
- 限次数
- 仅基础文本展示

### 会员版

- 完整转写
- TXT / SRT 导出
- 视频总结
- 批量处理
- 高级格式
- API

### 高级会员 / 单独计费

- 抽帧
- 音频提取
- 歌曲识别
- 大文件处理
- 优先队列

## SEO / 增长建议

- 每个工具独立落地页
- 每个页面独立 title / description
- 英文 / 中文 / 西班牙语 / 葡萄牙语优先
- 增加 FAQ、教程、示例
- 为结果页补结构化数据

## 当前最稳的落地方式

先把“视频转文字”做成稳定入口，再逐步把总结、抽帧、音频、识别拆成独立工具页。这样可以：

- 最大化复用现有代码
- 降低后端风险
- 让 SEO 页面持续增长
- 保持会员付费点清晰
